# ШмиркаТа — тест план (от край до край)

Автоматични тестове, които пускат **цялата Шмирка на този компютър** и я цъкат като истински хора
(2–3 браузъра едновременно), без да пипат продукцията.

## Как се пуска

```
cd e2e
npm install                    # веднъж
npx playwright install chromium  # веднъж
npm test                       # всичко (~6 мин, 63 теста)
npm test -- tests/05           # само един файл
npm test -- -g "Paint Wars"    # само тестове с това в името
npm run test:headed            # с видими прозорци
npm run report                 # HTML отчет (снимки, видео и trace на провалите)
```

От корена на репото: `npm run e2e`.

## Какво се случва при пускане (`run.mjs`)

1. Build на `packages/shared`.
2. **Нов, празен Postgres** (npm `embedded-postgres`, порт 54329, папка `e2e/.pgdata`, UTF-8) → `prisma migrate deploy`
   (така се проверяват и всички миграции върху празна база).
3. Server (4610), media server / mediasoup (4710, WebRTC на 44450, IP 127.0.0.1) и Vite клиент (5610) със собствен
   `JWT_SECRET` и без продукционни ключове.
4. **Предпазител:** базата трябва да е `localhost`, процесите стартират от `e2e/` (за да не се зареди `server/.env`
   с продукционната база), а след старт се регистрира "canary" потребител и се търси директно в локалната база.
   Ако го няма, всичко спира.
5. `playwright test` → накрая всички процеси и базата се спират. Логове: `e2e/logs/*.log`.

Chromium е с фалшив микрофон (пиукане) и камера (тестова картина), така че гласът и видеото се тестват реално:
тестовете четат WebRTC статистиката (байтове, които наистина са минали през SFU-то), а не само какво показва UI-то.

## Не е покрито автоматично (ръчно, с приятели)

- Десктоп приложението (Electron): глобален push-to-talk, отдалечен контрол, овърлей в игрите, самообновяване.
- Android APK (push известия, CallService).
- Вход с Google/Microsoft, имейли за забравена парола (Brevo), GIPHY, yogurthub музика, качване в Cloudinary
  (картинки, гласови съобщения, клипове) — външни услуги с ключове, които тестовете нарочно нямат.
- Клавиши (глобални), клипове (качват се в Cloudinary), гласови съобщения, push-to-talk.
- Музиката и 📺 ползват истинския YouTube (oEmbed + iframe) — тези тестове искат интернет.
- Качество на стрийма под натоварване (fps/битрейт на истински игри).

## Бъгове, намерени при първото пускане (2026-11-21)

1. **Сървърът падаше целият** при две едновременни влизания по покана (`P2002` в `joinServer` → необработен async
   reject → Node спира процеса → на Render рестарт, всички падат от гласа). Поправено: влизането е идемпотентно,
   а async грешките в route-овете отиват към error handler-а (`server/src/utils/asyncErrors.ts`).
2. **„Смяна на паролата“** на входа пише „Имейл или потребителско име“, а сървърът търсеше само по имейл.
3. **Приключена анкета** изглеждаше отворена до 30 s (клиентът сравняваше с часовник, който тиктака на 30 s). Сървърът
   вече праща `closed`.
4. **Глас: „не чувам/не виждам X“** — ако някой включи микрофон/камера/стрийм точно докато ти влизаш (преди recv
   транспорта), producer-ът се изхвърляше мълчаливо. Без поправката тестовете падаха 2/15 пъти, с нея 15/15.
5. **Телефон:** списъкът с членове беше отворен по подразбиране и покриваше целия чат при първо влизане в канал.
6. **🔕 „Включи канала“ / „Включи сървъра“ не работеше** (втори кръг тестове): менюто за заглушаване оставяше
   „изтекъл“ слушател (неотменен таймер в useEffect), който затваряше следващото меню при първия клик — заглушеното
   оставаше заглушено завинаги.
